AI:AT challenge · Regulatory Radar

Which rules need attention first, for my country and my sectors?

A self-hosted radar for chambers and associations: EU and national channels in every language, one entry per procedure, ranked by actionability.

One command

docker compose up, offline by default, Postgres as the only state.

4-step pipeline

Deterministic ingest, then translate, embed and group, then classify country × NACE.

Three interfaces

Angular UI, OpenAPI-first REST, MCP generated from the same spec.

1 · Problem research

What I looked at, and what it decided

Sources (probed by hand)

  • EUR-Lex CELLAR SPARQL: answers in ~4 s, CELEX sectors 3/5, EuroVoc subjects
  • BOE open data: one JSON summary per day; 404 on days without an issue
  • Sejm API works too; Council, Think Tank and TRIS are bot-filtered or slow

Decision: date-addressable official APIs, so the watermark is a day.

Standards

  • NACE Rev. 2.1 only (1,047 codes + Eurostat explanatory notes)
  • Seed tags and example profiles are Rev. 2: mapped once at the edge with Eurostat's correspondence table, not 1:1 (G47 → G47.1–G47.7, G47.9, J60.39)
  • CELEX / BOE ids as refs, ISO 3166 / 639 / 8601, RFC 9457 errors

Data semantics

  • Jurisdiction ≠ channel (TRIS carries national drafts)
  • nace_tags: [] does not decide relevance
  • Reactions and language versions are not new procedures

3 · Trade-offs

The interesting decisions

QuestionDecision
Threshold?Recall first: default view shows relevant + borderline; stated NACE tags are always relevant.
Can an LLM remove an item?No. It can add and rank. A pair that was relevant once stays tracked.
Same procedure?Shared ref or reaction (union-find, deterministic) plus agent joins with stored rationale. "When unsure: separate."
Reproducible with an LLM?Results stored with engine id and reused (temperature 0 where the model supports it); ranking is pure SQL.
Data in NACE Rev. 2?Mapped once where it enters, with Eurostat's correspondence; recall first, so a little broader than the original, and documented per profile.
EU-only inference?Possible: Mistral's EU endpoint (MISTRAL_SERVER_URL=https://api.eu.mistral.ai). It has no web search (function calling only), so the global endpoint is the default; in the EU the agents only open known public pages with fetch_url.
Where does operator data go?Nowhere: classification is profile-independent, and the profile only filters indexed labels.
Slow source?Timeouts plus bounded back-off; a failed day keeps the watermark back and shows degraded.

4 · What happens underneath

Ranking and relevance in two indexed queries

Open window Upcoming vote Standstill In procedure Adopted Information

radar_actionability(points, stage, as_of)

One immutable SQL function, the only ranking definition. Ties: date, verdict, publication, group key.

Hierarchical NACE match

Label paths NACE.C.C24.C24_4; the selection C24 becomes the lquery {NACE.C.C24.*, NACE.C, NACE}, served by GiST.

Dedup + memory

SHA-256 of canonical JSON is unique. Group snapshots are written only when content changes; first-seen time drives "new since I acknowledged".

Two modes, two databases

radar_offline / radar_online, chosen by LLM_PROVIDER plus its key.

4 · The two agents (online)

LangGraph agents with tools, checked in code

Grouping: same procedure?

  • Reviews every group; again when new evidence arrives
  • Gets identifiers (CELEX, procedure, Ares, TRIS, ELI) and pre-computed candidates
  • Tools: embedding neighbours, full-text, read-only SQL, provider web search
  • Joins only with high confidence and the same jurisdiction (code guard)

Classification: which sectors?

  • Semantic NACE search over Eurostat notes, embedded once per model
  • Every code checked; Rev. 2 codes sent back with the Rev. 2.1 hint
  • Context: action points, rule hints, labels of similar procedures
  • Safety net: rule sectors it skipped are added as borderline

Extended set: three independent sub-agents labelled without seeing the standard labels (158 of 159 agree) and a sceptical reviewer changed nothing. Where the standard set differs (4 labels, argued in data/eval/disagreements.md), we follow the extended set: hence strict recall 0.86 and tier agreement below 1 on the standard set. Profiles are scored with their Rev. 2.1 selections. Groups also carry the same names as in the labels. Honest caveat: the offline lexicon is tuned on these items, so these are training-set scores. Also checked: jurisdiction leaks 0, why-relevant coverage 100 %, ranking deterministic, tiers ordered. Online needs a key; its wiring is covered by an integration test with a scripted LLM.

2 · Agentic practice

How I worked with the agent

Setup

AGENTS.md (rules: spec first, append-only DB, Rev. 2.1 only, functional, dedup, 100 % docs), a pre-commit gate, sub-agents for the UI and for independent labelling, and parallel sessions that agreed on file ownership by message.

Verification

Each step was run in the real stack: tests on the real seed, testcontainers with Postgres 19, Playwright (incl. no overflow at 390 px), a live-source smoke run and a screenshot loop on desktop and phone.

Where it went wrong

  • It overfitted the offline lexicon to the eval set
  • Untyped SQL parameters passed typecheck but failed at runtime
  • A first agent-graph draft built a conversation providers reject
  • "Failing tests" turned out to be a full Docker disk
  • Its first Rev. 2 mapping kept G47 as G47; replaced by the official correspondence
  • A global i18n provider pulled 230 kB into every page load
